# 75,040-parameter Infini experiment

This is a separate model trained from random initialization; it is **not** a compressed version of the 117M weights, and it is not the pinned production model. The small model uses a new 672-token byte-level BPE vocabulary learned only from its training text, a 128-token context, four 32-wide layers and tied embeddings. `llm/tiny75k.json` specifies the architecture. The precise count is 75,040 trainable parameters; tokenizer data is separate from that count.

`learning/tiny75k-dataset.mjs` builds an approximately 25,000-conversation training corpus from synthetic teacher dialogues and repeated hand-written short conversational lessons. It excludes all exact held-out greeting phrasings from training and verifies that the existing fixed benchmark does not appear in the training shards. These are synthetic, narrow examples, not a general language corpus; repetition for many steps does not create new knowledge. The reported token count is exposure, not unique text. Long conversations exceeding the context are dropped and counted in the dataset manifest.

The `Train the 75k-parameter Infini model` workflow runs on CPU. It plans up to 100,000 steps (102.4 million token positions at batch 8 × 128) across up to 24 five-minute chunks, whichever limit is reached first. Each completed chunk publishes an immutable checkpoint with optimizer and RNG states, a checksum, a model export, held-out validation loss, and raw greeting responses to a dedicated GitHub prerelease `infinity-tiny75k-<run-id>`. Early stopping, cancellation, resource limits, or failure can prevent the target from being reached; inspect the latest status JSON to know actual steps and tokens. The dataset and tokenizer snapshot are published before training, so resuming uses precisely the same data rather than rebuilding a potentially different synthetic corpus.

For a continuation, manually run the workflow with `resume_release` set to the earlier `infinity-tiny75k-<run-id>`; it verifies and resumes the latest complete checkpoint in that release, restores the dataset and tokenizer, and saves progress to a new release. A `state: done` checkpoint has already completed the target cycle and will not continue beyond it without a deliberately configured new training cycle.

The raw `probes-XX.json` contains 13 exact held-out greetings (including the ten previously asked of the 117M model) and three seen examples, generated without rule-based fallback. These are diagnostic outputs, not an automatic accuracy score; review them for relevance and factual correctness. Validation loss on repeated synthetic dialogue is not proof of general chatbot ability. A 75k model is highly capacity-limited and may be less capable than the 117M model regardless of training time. Do not replace production without explicitly checking results and preserving rollback.
